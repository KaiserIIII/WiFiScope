# 新手操作与解释边界

启动后是“新手引导”。三个任务分别是了解本机配置、检查明确的设备/服务、读懂已有文件；离线演示可先熟悉操作。启动、导入、演示和切换模式不会自动进行目标检查。演示全部是合成证据，不能作为真实复测。

## 三步路径

1. 选择“了解这台电脑”或离线演示。本机检查读取配置，不证明互联网可用。已有文件请明确选择格式与替换/合并；XML 不猜测类型，导入不会触发复测。
2. 先看覆盖、执行状态和未知，再读“先做什么”的最多三条当前发现。结果按优先级排列；置信、检测状态与优先级分开。开放端口不等于漏洞，ARP 差异不能确认攻击，扫描器主张待独立验证。没有发现也不能证明安全。
3. 底部“导出脱敏报告”写入尚不存在的新目录。当前操作、取消、导出和顶部模式切换始终可达，正文滚动。需要全部发现和选中证据，点击“专业工作台”；报告、案件 ID、本地处置和当前工作继续保留。

## 指定设备检查

填写单个主机名或 IP；新手不接受 CIDR，不推测网关、子网或公共测试地址。默认 TCP 80、443；可选同一主机的 HTTP/HTTPS URL 请求 HEAD 策略检查。URL 不允许账号、查询、片段，不跟随重定向、不读取正文、不保留 Cookie 值。443 和 HTTPS URL 端口有正常 TLS 验证，不绕过失败。

先点“预览检查计划”，无解析/连接副作用。预览列出规范化主机、全部 TCP 端口、TLS 端口、HEAD URL、每个地址的连接次数，以及按最多 4 次/秒计算的规划估算时长。默认每地址 2 TCP + 1 TLS = 3 次、规划估算约 0.75 秒（首次连接可立即开始）；URL 可以增加 TCP/TLS/HEAD 项。主机名解析前不知道地址数量，最多每族 2 个地址、合计 4 个；解析失败可能没有连接。首次启动时机、解析、超时和限速使实际耗时可能更短或更长，不保证完成。

核对后勾选底部相邻的未选中授权框，再开始。任何目标/URL 修改都会清除预览和授权。取消使用已有协作机制，保留已经取得的部分观测；未知、失败、未检查不能当作通过。

## 文件、隐私和专业深度

导入明确区分 Nmap XML（资产/端口）、Greenbone XML（扫描器主张）、pcap/pcapng（离线元数据）、netsh/nmcli（Wi-Fi 文本）、WiFiScope JSON。默认替换，合并需显式勾选。格式错误会提示检查格式、大小和权限；独立脱敏文件合并会解释身份无法可靠关联。

新手导出固定脱敏，保留每次导出内的关联，排除本地备注。脱敏不保证匿名，也不保证不同导出之间的身份对应。专业工作台中“本次导出包含原始标识符”仅作用于专业导出；“保存案件时保留原始标识符”仅作用于后续案件快照。两项互相独立，需分别明确选择。切回新手不会让专业的原始导出选项生效。

三项安全工具在两种模式的顶部均可达。工具窗口保留独立结果，打开/关闭/切换不采集；漏洞审计为本地匹配，抓包需单独授权，热力图点击后还要明确采样。工具窗口底部导出有自己的“原始标识符”选择，初始不勾选，不继承专业主窗口选择；它不控制原始包留存，也不控制案件保存。工具“应用”旁显示替换后果，需明确勾选，随后才替换主快照并重置旧处置关联。背景/原始包/路径/备注与任意导入描述不进入普通报告，即便选择原始标识符。

专业模式保留精确范围、端口、快速检查、所有表格、来源时间、结构化证据、持久化 ID、处置、案件历史/验证/比较。CLI 使用 `python -m wifiscope --help`，示例在中英文 README。数量比较显示双方数量与覆盖，不关联独立脱敏的身份；0 不能证明干净审计，不宣称自动修复。

## 小词典

| 词语 | 如何理解 |
| --- | --- |
| Wi-Fi 名称 / SSID | 网络显示名，同名不保证来自同一可信网络 |
| 信号 | 当前观测位置的无线强度，不能代表带宽或连接质量 |
| IP 地址 | 用于定位网络端点；一个主机名可对应多个地址 |
| 端口 | 服务入口；可连接不代表存在漏洞 |
| TLS / 证书 | 加密协商与身份验证；失败原因需结合时钟、名称和信任链核查 |
| 覆盖缺口 | 没检查到、无法取得或范围不足的证据，不能当作安全 |
| 优先级 / 置信 / 检测状态 | 分别表示处理顺序、证据把握程度、观察或导入待验证；本地处置是另一个工作流字段 |
| TCP 耗时 | 建立连接的耗时，不是带宽、ICMP 丢包率或应用响应时间 |

解释由本地受控规则生成，不调用模型或外部服务，不引用任意导入描述、Cookie 值或备注。详细能力矩阵见[能力对照](competitive-landscape.md)。原生窗口测试与合成视觉检查并不是用户研究，不声称已证明对所有新手都易用。
# Indexed catalog / inventory desktop

两种模式均可点击“漏洞库与资产清单”：① 打开/新建本地索引；② 查找并选择详情中的身份，填写自己的资产标签/版本，或明确导入清单；③ 运行预览并先看模型匹配、未知、不匹配、未评估数量。不会要求新手手写 CPE/JSON；公告中的受影响版本和环境不会自动成为资产事实。

专业详细设置提供源文件选择、按顺序的展开 SHA256、数据库 SHA256、新目标及工作预算。新建只允许新文件，查询每页 20 条，输入变更会清空旧页及应用资格。清单表可选择并移除组件；同标签的声明项加入同一资产，不关联当前采集地址。导入文档与手工声明需显式新建清单后切换，以保留来源计数单位。SBOM 只是未核实身份；时间缺失保持未知。Nmap 请明确选 `nmap` 格式，再选择已有本地 XML 并点击导入；不启动扫描器。预览逐主机地址及服务/OS 来源，`asserted` 是来源探测主张，`possible` 是可能假设，不证明存在或不存在；OS 替代假设不能拼成已确认环境。专业来源信息保留协议、端口、方法、置信度/准确度、来源时间和 URI 转换绑定；来源尺度不是漏洞概率。

选择清单中的组件后，可明确设置 numeric / semver2 / openssh-portable，默认 unknown。这是分析者的排序选择，不是扫描发现；不改变原始版本大小写、来源、计数或假设状态。修改使旧预览失效，需要重新运行审计。移除保留源计数、更新保留/未保留主机数并标记部分；未保留主机可能包括明确移除。输入来源错误或缺少扫描完成状态也标记部分；工作限额中未评估数量可保持未知，不是零。

完整合成演练明确创建并清理临时索引，覆盖两个供应商、CNA-only、正反对照和缺失环境；不改用户已选目录/清单，不替换旧小目录演示。所有工作通过共享后台队列；关闭会取消并忽略过期结果。目录元数据不能应用为报告。预览通过验证后才可在底部明确勾选应用，或默认脱敏导出；现有案件/处置在应用前保留。键盘可 Tab 聚焦，工具页支持滚轮及 PageUp/PageDown 滚动。自动化 Tk 测试不代表已完成人类新手研究。
